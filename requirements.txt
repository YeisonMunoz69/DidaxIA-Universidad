# Identidad delegada (DD-18, D-16 · PM-B15 A). Es la biblioteca oficial de
# Google para verificar un id_token contra sus claves públicas — reescribir
# esa verificación a mano sería repetir código de seguridad que ya existe y
# está mantenido. Solo se usa `google.oauth2.id_token` y
# `google.auth.transport.requests`, no el resto del paquete.
#
# ⚠️ `[requests]` es del 2026-09-01 y no es cosmético. `google.auth.transport.
# requests` **necesita `requests`**, que `google-auth` declara como extra y no
# como dependencia. Hasta hoy funcionaba por accidente: `sentence-transformers`
# lo arrastra, así que en el equipo y en la imagen estaba puesto. En un entorno
# que instale este archivo **sin el codificador** —el que basta para ejecutar la
# suite offline— la recolección se interrumpe entera con
# `ImportError: The requests library is not installed`, y se lleva por delante
# los diez módulos que tocan identidad.
#
# Es el mismo defecto que `httpx2` tuvo el 2026-09-01: una dependencia real que
# llegaba por otra vía y que nadie declaraba.
google-auth[requests]>=2.28,<3

# Validación estructural del PDF de la autorización del representante
# (`EQ-021`, hito R4). Hasta el cierre V-B «PDF validado» significaba comprobar
# cinco bytes —`%PDF-`—, y eso aceptaba un archivo truncado, uno cifrado que el
# equipo no puede abrir o un `.txt` con la cabecera puesta. Una autorización
# firmada por un representante legal que no se puede abrir no es evidencia de
# nada, y descubrirlo seis meses después es descubrirlo cuando ya no hay a quién
# pedirle otra copia.
#
# Se usa SÓLO para comprobar que el archivo abre y tiene páginas: no se extrae
# texto, no se leen metadatos y no se registra nada de su contenido. Ver
# `adaptadores/entrantes/http/pdf.py`.
#
# Es la biblioteca mantenida del formato; escribir a mano un analizador de tabla
# de referencias cruzadas, objetos indirectos y flujos comprimidos —sobre un
# archivo que llega de fuera— sería reimplementarla mal.
pypdf>=5,<7
